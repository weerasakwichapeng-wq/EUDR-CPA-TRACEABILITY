# ระบบตรวจสอบย้อนกลับวัตถุดิบ EUDR — ยางพารา

เว็บแอปสำหรับตรวจสอบย้อนกลับแหล่งที่มาวัตถุดิบยางพารา และควบคุมปริมาณรับซื้อด้วยระบบตัดโควต้ารายแหล่ง
สร้างจากไฟล์ `2026 Master POLYGON EUDR CPA (Real).xlsx`

---

## วิธีเปิดใช้งาน

**วิธีที่ 1 — เปิดผ่านเซิร์ฟเวอร์ (แนะนำ)**

```bash
node eudr-web/serve.js
```

แล้วเปิดเบราว์เซอร์ไปที่ `http://localhost:8777`

**วิธีที่ 2 — ดับเบิลคลิก** ไฟล์ `eudr-web/index.html` ได้โดยตรง (ไม่ต้องติดตั้งอะไร)

> ภาพแผนที่ดาวเทียม/แผนที่ถนนดึงจากอินเทอร์เน็ต ถ้าออฟไลน์ระบบยังใช้งานได้ทุกส่วน
> เพียงแต่แผนที่จะไม่มีภาพพื้นหลัง (กดปุ่ม 🛰 เพื่อสลับเป็น "ไม่มีพื้นหลัง")

## การแบ่งประเภทแหล่งวัตถุดิบ

| ประเภท | ที่มาในไฟล์ Excel | จำนวนแหล่ง | แปลง | พื้นที่ (ไร่) |
|---|---|---:|---:|---:|
| **สวนรายใหญ่** | ชีต `1.1`–`1.4` | 4 | 264 | 5,868.25 |
| **ส่งเสริม** | ชีต `2.ส่งเสริม` | 145 | 252 | 2,913.83 |
| **ผู้รวบรวม** | ชีต `3.1 พ่อค้า สปก.`, `3.พ่อค้า โฉนด`, `เอกสารสิทธิ์รวม`, `List` | 74 | 6,447 | 75,230.87 |
| **รวม** | | **223** | **6,963** | **84,012.94** |

ยอดพื้นที่ตรงกับชีตสรุป `พื้นที่ทั้งหมด(ไร่)` ของไฟล์ต้นทางทุกรายการ
(โฉนด 30,230.82 ไร่ · ส.ป.ก. 53,782.13 ไร่)

**หมายเหตุการจัดประเภท**

- ชีต `เอกสารสิทธิ์รวม` (นายกิตติชัย นารีนุช) จัดอยู่ในกลุ่ม **ผู้รวบรวม** เพราะมีโครงสร้าง
  ผู้รวบรวม 1 ราย → เกษตรกรหลายราย เหมือนกลุ่มพ่อค้า โดยระบุกลุ่มย่อยว่า `เอกสารสิทธิ์รวม`
- ชีต `List` เป็นทะเบียนหมู่บ้าน ↔ ผู้รวบรวม ใช้เป็น **ชื่อมาตรฐาน** ของผู้รวบรวม
  (ชีตพ่อค้ามีการสะกดชื่อคลาดเคลื่อนหลายแบบสำหรับรหัส CV เดียวกัน)
  ผู้รวบรวม 13 รายในชีต `List` ที่ยังไม่มีแปลงในระบบ ถูกนำเข้ามาด้วยและติดป้าย "ยังไม่มีแปลง"
- รหัส CV ถอดจากรหัสแปลง (เช่น `S_308068600_LEI_ML72` → `308068600`)
  เพราะคอลัมน์ CV ในบางชีตวางเยื้องคอลัมน์
- แปลงจากชีต `1.4 ธนวัฒน์ เกิดช่วย` ระบุเป็นเอกสารสิทธิ์ **น.ส.3** ตามหมายเหตุในไฟล์ต้นทาง

## แผนที่ดาวเทียมและขอบเขตการปกครอง

หน้า **ภาพรวม** มีแผนที่แสดงแปลงปลูกทั้งหมด 6,963 แปลงทับบนภาพถ่ายดาวเทียม
กรองได้ตามประเภทแหล่ง และตาม จังหวัด → อำเภอ → ตำบล (ตัวเลือกลดหลั่นตามกัน)
คลิกที่แปลงเพื่อเปิดรายละเอียดและพิกัด

ปุ่มควบคุมมุมขวาบนของแผนที่

| ปุ่ม | หน้าที่ |
|---|---|
| `+` `−` `⤢` | ขยาย · ย่อ · จัดกรอบให้พอดี |
| `☰` | เปิดแผงเลือกชั้นแผนที่ |

แผง `☰` แบ่งเป็นสองส่วน เลือกอิสระต่อกัน และจำค่าที่เลือกไว้ให้

**ภาพพื้นหลัง** (เลือกได้อย่างเดียว) — ภาพดาวเทียม · แผนที่ถนน · ไม่มีพื้นหลัง

**ขอบเขตการปกครอง** (ติ๊กได้หลายชั้นพร้อมกัน)

| ชั้น | เส้น | หมายเหตุ |
|---|---|---|
| จังหวัด | ขาวหนา | 18 จังหวัด |
| อำเภอ | เหลืองทึบ | 143 อำเภอ |
| ตำบล | ประขาว | 968 ตำบล — แสดงเมื่อซูมตั้งแต่ระดับ 10 ขึ้นไป |

**พื้นที่อนุรักษ์** (ติ๊กได้หลายชั้นพร้อมกัน) — ระบายสีทึบจาง ๆ ทับภาพดาวเทียม

| ชั้น | สี | จำนวน |
|---|---|---:|
| อุทยานแห่งชาติ | แดง | 23 |
| เขตรักษาพันธุ์สัตว์ป่า | ม่วง | 12 |
| วนอุทยาน | ส้ม | 20 |
| เขตห้ามล่าสัตว์ป่า | เขียวน้ำทะเล | 6 |

ชื่อเขตจะขึ้นเมื่อพื้นที่บนจอใหญ่พอ และหลบไม่ให้ทับกัน จังหวัดได้ที่ก่อน แล้วอำเภอ ตำบล แล้วพื้นที่อนุรักษ์

## การตรวจแปลงทับเขตอนุรักษ์

ระบบตรวจทุกแปลงเทียบกับขอบเขตพื้นที่อนุรักษ์ 61 แห่ง แล้วแยกเป็นสองระดับ

| ผล | เกณฑ์ | แสดงผล |
|---|---|---|
| **อยู่ในเขต** | จุดศูนย์กลางแปลงตกอยู่ในเขตอนุรักษ์ | ป้ายแดง |
| **ขอบล้ำเข้า** | จุดศูนย์กลางอยู่นอกเขต แต่มีมุมแปลงล้ำเข้าไป | ป้ายเหลือง |

**ผลการตรวจปัจจุบัน: พบ 16 แปลง รวม 104.48 ไร่** — อยู่ในเขตทั้งแปลง 10 แปลง · ขอบล้ำเข้า 6 แปลง

| เขตอนุรักษ์ | แปลง | ไร่ |
|---|---:|---:|
| เขตรักษาพันธุ์สัตว์ป่าภูหลวง | 3 | 42 |
| วนอุทยานหริรักษ์ | 3 | 32 |
| เขตห้ามล่าสัตว์ป่าเขาน้อย-เขาประดู่ | 9 | 22 |
| วนอุทยานพระพุทธบาทบัวบก | 1 | 8 |

ดูรายการเต็มได้ที่หน้าภาพรวม หัวข้อ "แปลงที่ทับซ้อนเขตอนุรักษ์" คลิกแถวเพื่อเปิดแผนที่แปลงนั้น
กรองเฉพาะแปลงกลุ่มนี้ได้ที่แท็บแปลงปลูก และส่งออกเป็น GeoJSON แยกได้ที่แท็บรายงาน
บนแผนที่ แปลงกลุ่มนี้ตีกรอบสีแดงให้เห็นชัด

> **ข้อจำกัดที่ต้องเข้าใจ** ผลนี้ใช้ขอบเขตจาก OpenStreetMap ซึ่งเป็นข้อมูลอาสาสมัคร
> **ไม่ใช่แนวเขตตามกฎหมาย** ใช้เป็นสัญญาณเตือนให้ไปตรวจสอบต่อเท่านั้น
> ก่อนสรุปว่าแปลงใดมีปัญหาจริง ต้องเทียบกับแนวเขตทางการจากกรมอุทยานแห่งชาติฯ
> หรือกรมป่าไม้ และไม่ควรถือว่าแปลงที่ระบบไม่ได้ทำเครื่องหมายไว้คือแปลงที่ปลอดภัยแน่นอน

### ผลตรวจสอบความถูกต้องของชั้นข้อมูล

ตรวจแล้วผ่านทุกข้อ: วงขอบเขตปิดครบทุกวง · ไม่มีชื่อซ้ำ · ทุก relation ต่อวงได้สมบูรณ์ ·
การย่อจุดทำให้พื้นที่คลาดเคลื่อนน้อยกว่า 0.04% · คำนวณผลทับซ้อนใหม่แบบอิสระได้ 16 แปลงตรงกัน

**แต่ความแม่นของเส้นขอบเขตเองไม่เท่ากันทุกแห่ง** เทียบพื้นที่ที่คำนวณจากรูปทรง OSM
กับพื้นที่ประกาศอย่างเป็นทางการ

| เขตอนุรักษ์ | คำนวณจาก OSM | ประกาศ | ต่าง |
|---|---:|---:|---:|
| เขตรักษาพันธุ์สัตว์ป่าภูเขียว | 1,572 | 1,560 | +0.7% |
| อุทยานแห่งชาติภูหินร่องกล้า | 305 | 307 | −0.6% |
| อุทยานแห่งชาติทุ่งแสลงหลวง | 1,275 | 1,263 | +1.0% |
| เขตรักษาพันธุ์สัตว์ป่าภูหลวง | 909 | 898 | +1.2% |
| อุทยานแห่งชาติน้ำหนาว | 979 | 966 | +1.3% |
| อุทยานแห่งชาติภูเรือ | 123 | 121 | +1.5% |
| **อุทยานแห่งชาติภูกระดึง** | **261** | **348** | **−25%** |

(หน่วย ตร.กม. · ตัวเลขพื้นที่ประกาศเป็นค่าอ้างอิง ควรตรวจยืนยันกับกรมอุทยานฯ อีกครั้ง)

ส่วนใหญ่ต่างกันราว 1% ซึ่งรับได้ **แต่ภูกระดึงเส้นขอบของ OSM เล็กกว่าพื้นที่ประกาศถึง 25%**
แปลว่าแปลงที่อยู่นอกเส้นเล็กน้อยอาจยังอยู่ในเขตอุทยานจริง — **ตัวเลข 16 แปลงจึงเป็นค่าต่ำสุด
ของจำนวนที่อาจมีปัญหา ไม่ใช่ตัวเลขสุดท้าย**

### พื้นที่ที่ระบบตัดออกโดยตั้งใจ

- เขตอนุรักษ์ฝั่ง สปป.ลาว 4 แห่ง (อยู่นอกขอบเขตที่เกี่ยวข้อง)
- รูปทรงที่ไม่มีชื่อ 4 รายการ — ในจำนวนนี้ **อุทยานแห่งชาติแก่งเจ็ดแคว** (พิษณุโลก)
  ข้อมูล OSM ระบุไว้เองว่า "ขอบเขตนี้เดาล้วน ๆ ใส่ไว้เป็นตัวแทนชั่วคราว" จึงไม่นำมาใช้
  ทั้งที่มีแปลงอยู่ในจังหวัดพิษณุโลก 3,482 ไร่ — **ต้องขอแนวเขตจริงมาตรวจเพิ่ม**

### ป่าสงวนแห่งชาติ — ยังไม่มีในระบบ

หาแนวเขตป่าสงวนแห่งชาติจากแหล่งสาธารณะไม่ได้

- OpenStreetMap ไม่มีข้อมูลนี้เลยในพื้นที่ที่ตรวจ (ค้นแล้วได้ 0 รายการ)
- ArcGIS ของกรมป่าไม้ (`gis.forest.go.th`) เข้าไม่ถึงจากเครื่องนี้
- ArcGIS ของกรมอุทยานฯ (`gisportal.dnp.go.th`) ต้องใช้โทเคน

ถ้าขอไฟล์แนวเขตจากกรมป่าไม้มาได้แล้ว ให้แปลงเป็น GeoJSON (WGS84) วางไว้ที่
`tools/cache/reserved_forest.geojson` แล้วรัน `node tools/build-protect.js` ใหม่
ระบบจะเพิ่มเป็นชั้น "ป่าสงวนแห่งชาติ" และตรวจการทับซ้อนให้อัตโนมัติโดยไม่ต้องแก้โค้ด

### ภาพดาวเทียมทำงานอย่างไร

| เปิดจาก | แหล่งภาพ | ความละเอียด |
|---|---|---|
| เครื่องตัวเอง (`serve.js` หรือดับเบิลคลิก) | โหลดสดจากอินเทอร์เน็ต | คมทุกระดับซูม |
| ลิงก์ที่แชร์ (Artifact) | ภาพที่ฝังไว้ในไฟล์ | คมถึงซูม 12 · เกินกว่านั้นขยายจากภาพเดิม (เบลอ) |

หน้าเว็บที่เผยแพร่เป็นลิงก์ถูกนโยบายความปลอดภัยปิดกั้นการโหลดภาพจากเซิร์ฟเวอร์ภายนอก
จึงฝังภาพดาวเทียมเฉพาะบริเวณที่มีแปลงไว้ในไฟล์ 377 ไทล์ (7.7 MB) ระบบตรวจเองว่าโหลดสดได้ไหม
ถ้าไม่ได้จะสลับไปใช้ภาพที่ฝังไว้อัตโนมัติ และเขียนบอกไว้ใต้แผนที่ว่ากำลังใช้แหล่งไหนอยู่
ภาพที่ฝังไว้ยังทำหน้าที่เป็นตัวสำรองตอนเปิดในเครื่องแบบออฟไลน์ด้วย

### การจับคู่แปลงกับเขตปกครอง

ระบบคำนวณจุดศูนย์กลางของทุกแปลงแล้วตรวจว่าตกอยู่ในตำบลใด (point-in-polygon)
**จับคู่ได้ 6,962 จาก 6,963 แปลง** ทำให้ทะเบียนแปลงมี ตำบล/อำเภอ/จังหวัด ที่มาจากพิกัดจริง
ไม่ใช่จากรหัสในไฟล์ Excel

> **ข้อสังเกตสำคัญ** — ไฟล์ Excel ระบุจังหวัดเป็น `LEI` (เลย) ทุกแถว แต่เมื่อตรวจจากพิกัดจริง
> พบว่าฐานวัตถุดิบกระจายอยู่ **6 จังหวัด**:
>
> | จังหวัด | พื้นที่ (ไร่) | แปลง |
> |---|---:|---:|
> | เลย | 57,427 | 5,068 |
> | อุดรธานี | 10,855 | 712 |
> | หนองคาย | 8,522 | 706 |
> | หนองบัวลำภู | 3,696 | 236 |
> | พิษณุโลก | 3,482 | 238 |
> | บึงกาฬ | น้อย | น้อย |
>
> รวม 140 ตำบล — ควรตรวจสอบว่าตรงกับขอบเขตที่ขึ้นทะเบียนไว้กับ FSC/EUDR หรือไม่
> ในหน้ารายละเอียดแปลงจะแสดงทั้ง "ที่ตั้งตามขอบเขตการปกครอง" และ "อำเภอตามไฟล์ต้นทาง"
> ให้เทียบกันได้

### สูตรคำนวณ

```
โควต้าต่อปี (กก. ยางแห้ง) = พื้นที่ที่ใช้ได้ (ไร่) × ผลผลิตต่อไร่ต่อปี (กก./ไร่)
พื้นที่ที่ใช้ได้            = พื้นที่รวม − พื้นที่เสี่ยง (ถ้าเปิดใช้การหัก)
```

- **พื้นที่เสี่ยง** คือพื้นที่ไฮไลต์เหลืองในไฟล์ต้นทาง (นายธนา 357.69 ไร่ · ศุภบูรณ์ 282.63 ไร่)
- ค่าเริ่มต้นผลผลิตต่อไร่: สวนรายใหญ่ 280 · ส่งเสริม 250 · ผู้รวบรวม 250 กก./ไร่/ปี
  แก้ไขได้ที่แท็บ **ตั้งค่า** ให้ตรงกับผลผลิตจริงของพื้นที่
- กำหนดโควต้าเฉพาะรายเป็นตัวเลขตรง ๆ ได้ (override) แทนการคำนวณจากพื้นที่

### ข้อมูลที่บันทึกได้ต่อหนึ่งรายการ

วันที่รับซื้อ · เลขที่ใบชั่ง/ใบรับซื้อ · **Lot No.** · แหล่งวัตถุดิบ · ชนิดวัตถุดิบ ·
น้ำหนักรับซื้อ · %DRC · ราคา/กก. · หมายเหตุ · **ไฟล์แนบรูปใบชั่ง**

ค้นหารายการด้วยเลขที่ใบชั่ง Lot No. ชื่อแหล่ง หรือหมายเหตุได้ และทั้ง Lot No. กับจำนวนไฟล์แนบ
ติดไปกับไฟล์ CSV ที่ส่งออกด้วย

### ไฟล์แนบรูปใบชั่ง

ปุ่ม **แนบไฟล์รูปใบชั่ง** เลือกได้หลายไฟล์พร้อมกัน ส่วนปุ่ม **ถ่ายรูป** จะเปิดกล้องให้เลยเมื่อใช้บนมือถือ
รองรับไฟล์รูปทุกชนิดและ PDF (ไม่เกิน 8 MB ต่อไฟล์)

| เรื่อง | รายละเอียด |
|---|---|
| การย่อขนาด | รูปถูกย่อให้ด้านยาวสุดไม่เกิน 1,600 px แล้วบันทึกเป็น JPEG คุณภาพ 72% — ตัวเลขบนใบชั่งยังอ่านออก ไฟล์เหลือราว 70–200 KB |
| ที่เก็บ | IndexedDB ของเบราว์เซอร์ (ไม่ใช่ localStorage ซึ่งมีพื้นที่แค่ราว 5 MB ไม่พอเก็บรูป) |
| การเปิดดู | กดปุ่ม 📎 ในตารางรายการรับซื้อ จะเปิดรูปเต็มพร้อมข้อมูลใบชั่ง |
| การลบ | ลบรายการรับซื้อแล้วไฟล์แนบของรายการนั้นถูกลบตามไปด้วย |
| ไฟล์สำรอง | **รวมรูปใบชั่งไว้ในไฟล์สำรองด้วย** ไฟล์จะใหญ่ขึ้นตามจำนวนรูป กู้คืนแล้วได้รูปกลับมาครบ |

ถ้าเบราว์เซอร์ใช้ IndexedDB ไม่ได้ (เช่นโหมดส่วนตัวบางตัว) ส่วนแนบไฟล์จะถูกซ่อนไปเอง
และยังบันทึกรายการรับซื้อได้ตามปกติ

### ขอบเขตแปลงต้นทางของล็อต — ส่วนที่ใช้ยื่น DDS

EUDR มาตรา 9 ขอ **"พิกัดของแปลงทั้งหมดที่ผลิตสินค้านั้น"** ไม่ได้ขอน้ำหนักรายแปลง
และ EUDR **ไม่มีระบบ mass balance แบบ FSC** — ล็อตที่ผสมกันต้องประกาศทุกแปลงที่มีส่วนอยู่ในล็อตนั้น

ตอนบันทึกรับซื้อจึงต้องระบุขอบเขตแปลงต้นทาง สองแบบ

| แบบ | ใช้เมื่อไร |
|---|---|
| **ทั้งกลุ่ม** (ค่าตั้งต้น) | ล็อตรวมยางจากทั้งกลุ่มของผู้รวบรวม |
| **เลือกเฉพาะราย** | รู้ว่าล็อตนี้มาจากเกษตรกรรายไหนบ้าง — ติ๊กเลือกได้ มีช่องค้นหาชื่อ |

ระบบจะแสดงทันทีว่าขอบเขตที่เลือกมีกี่แปลง กี่ไร่ และโควต้าคงเหลือเท่าไร
ที่หน้ารายละเอียดล็อตมีปุ่มส่งออก **GeoJSON แปลงต้นทางของล็อตนี้** สำหรับแนบยื่น DDS โดยตรง

### การตัดโควต้า

บันทึกการรับซื้อที่แท็บ **รับซื้อ / ตัดโควต้า** ระบบจะแปลงน้ำหนักรับซื้อเป็น**น้ำหนักยางแห้ง**
แล้วตัดออกจากโควต้าของแหล่งนั้นในปีการผลิตของวันที่รับซื้อ

```
น้ำหนักยางแห้ง = น้ำหนักรับซื้อ × %DRC ÷ 100
```

ค่า %DRC ตั้งต้นตามชนิดวัตถุดิบ (ยางก้อนถ้วย 60 · น้ำยางสด 35 · ยางแผ่นดิบ 95 · เศษยาง 70)
แก้ไขเป็นค่าที่วัดได้จริงในแต่ละเที่ยวรถได้

### โหมดควบคุมเมื่อรับซื้อเกินโควต้า

| โหมด | พฤติกรรม |
|---|---|
| **เตือน** (ค่าเริ่มต้น) | แสดงกล่องยืนยันพร้อมจำนวนที่เกิน — บันทึกได้ถ้ายืนยัน |
| **ห้ามบันทึก** | ปิดกั้นการบันทึกทันที |
| **ไม่ควบคุม** | บันทึกได้โดยไม่ตรวจสอบ |

สถานะแต่ละแหล่ง: **ปกติ** (< 90%) · **ใกล้เต็ม** (≥ 90%) · **เกินโควต้า** (> 100%)
ปรับเกณฑ์เตือนได้ที่แท็บตั้งค่า

**ตรวจกับขอบเขตที่ระบุ ไม่ใช่แค่ยอดรวมทั้งกลุ่ม** — ถ้าระบุแค่ 3 ราย (11 แปลง 157.93 ไร่
โควต้า 39,483 กก.) แล้วรับซื้อยางแห้ง 16,200 กก. ระบบเทียบกับ 39,483 ไม่ใช่ 723,628 ของทั้งกลุ่ม
ถ้าระบุแคบกว่านั้นจนพื้นที่ผลิตไม่ไหว จะเตือนว่า "พื้นที่ที่ระบุผลิตได้ไม่ถึงปริมาณนี้"
นี่คือด่านจับการสวมสิทธิ์ยางนอกกลุ่ม ซึ่งตรงกับเกณฑ์ประเมินความเสี่ยงตามมาตรา 10
เรื่องการปะปนกับสินค้าที่ไม่ทราบแหล่งที่มา

### ระบบตัดโควต้าอัตโนมัติรายแปลง

ทุกรายการรับซื้อจะถูกตัดลงบัญชีโควต้าของแต่ละแปลงจริง (ไม่ใช่แค่เฉลี่ยตามสัดส่วนพื้นที่แบบเดิม)
ตามเงื่อนไข 3 ข้อ เรียงลำดับดังนี้

1. **ตัดจากพื้นที่ใกล้กันก่อน** — เริ่มจากตำบลที่แหล่งนั้นมีพื้นที่มากที่สุด (ตำบล "บ้าน")
   แล้วไล่ไปตำบลถัดไปตามระยะทางจริง (คำนวณจากพิกัดจุดกลางถ่วงน้ำหนักด้วยพื้นที่ของแต่ละตำบล)
2. **ภายในตำบลเดียวกัน ตัดแปลงใหญ่สุดก่อน** — เติมโควต้า**รายเดือน**ของแปลงนั้นให้เต็มก่อน
   แล้วค่อยขยับไปแปลงถัดไป ทำซ้ำจนน้ำหนักที่รับเข้าหมดพอดี
3. **คำนวณน้ำหนักรับเข้าเป็นยางแห้งก่อนเสมอ** แล้วจึงนำไปตัดตามเงื่อนไข 1–2

```
โควต้ารายเดือนของแปลง = โควต้าทั้งปีของแปลง × สัดส่วนผลผลิตเดือนนั้น (%)
```

สัดส่วนผลผลิตรายเดือนตั้งต้นแบ่งเท่ากันทุกเดือน (~8.33%) ปรับได้ที่แท็บตั้งค่า หัวข้อ
**"การกระจายผลผลิตรายเดือน"** แยกตามประเภทแหล่ง (สวนรายใหญ่ / ส่งเสริม / ผู้รวบรวม)
เช่น ลดสัดส่วนช่วงผลัดใบ (ก.พ.–เม.ย.) แล้วเพิ่มช่วงปลายปีให้ตรงกับฤดูกาลกรีดจริงของพื้นที่

**ถ้าทุกแปลงในขอบเขตเต็มโควต้ารายเดือนแล้วแต่ยังตัดไม่หมด** ส่วนที่เกินจะถูกกระจายตาม
สัดส่วนพื้นที่แทน และทำเครื่องหมาย "เกิน" ไว้ทุกแถวที่เกี่ยวข้อง — ก่อนบันทึกจะเห็นตัวอย่างการตัด
ในฟอร์มรับซื้อ (หัวข้อ "ตัวอย่างการตัดโควต้ารายแปลง") และระบบจะตรวจทั้งเกินโควต้าทั้งปีและ
เกินกำลังผลิตรายเดือนแยกกัน ก่อนใช้โหมดควบคุมเดียวกับด้านบน (เตือน/ห้ามบันทึก/ไม่ควบคุม)

### รายงานตัดโควต้ารายรอบ

หน้ารายละเอียดล็อต (คลิกแถวในตาราง "รายการรับซื้อ") แสดง **บัญชีที่ระบบตัดจริง** —
รายชื่อแปลง ลำดับที่ตัด ตำบล และจำนวนกิโลกรัมที่ตัดจากแต่ละแปลง พร้อมปุ่มส่งออก CSV เฉพาะล็อตนั้น
ส่วนแท็บ **รายงาน & ส่งออก** มีปุ่ม **"CSV — รายงานตัดโควต้าทุกรอบ (รายแปลง)"** ส่งออกบัญชีตัดโควต้า
ทุกรายการรับซื้อรวมกันเป็นไฟล์เดียว หนึ่งแถวต่อหนึ่งแปลงที่ถูกตัดในแต่ละรอบ

**ข้อแตกต่างจากรุ่นก่อนหน้า** — ตัวเลขนี้คือ "บัญชีที่ระบบตัดจริง" (deterministic, ทำซ้ำได้ผลเดิมเสมอ)
ไม่ใช่การเฉลี่ยตามสัดส่วนพื้นที่แบบเดา แต่ยังคงเป็น **การตัดสินใจภายในของระบบเพื่อควบคุมปริมาณ**
ไม่ใช่การชั่งน้ำหนักแยกรายแปลงจริงทางกายภาพ (ยางในล็อตผสมกันมาก่อนถึงมือผู้รวบรวม)
สิ่งที่ส่งออกไปยื่น DDS จริงคือรายชื่อแปลงกับพิกัด (หัวข้อ "ขอบเขตแปลงต้นทางของล็อต" ด้านบน)
ไม่ใช่ตัวเลขกิโลรายแปลงในรายงานนี้

รายการรับซื้อที่บันทึกไว้ก่อนมีระบบนี้ (หรือกู้คืนจากไฟล์สำรองรุ่นเก่า) จะไม่มีบัญชีตัดโควต้าจริง
ระบบจะแสดงค่าประมาณแบบเฉลี่ยตามสัดส่วนพื้นที่แทนโดยอัตโนมัติ พร้อมกำกับว่าเป็นค่าคำนวณย้อนหลัง

## การจัดเก็บข้อมูล — สิ่งที่ต้องระวัง

**ข้อมูลการรับซื้อและการตั้งค่าเก็บใน localStorage ส่วนรูปใบชั่งเก็บใน IndexedDB
ของเบราว์เซอร์เครื่องนั้น ๆ เท่านั้น**

- เปลี่ยนเครื่อง เปลี่ยนเบราว์เซอร์ หรือล้างข้อมูลเบราว์เซอร์ → ข้อมูลรับซื้อและรูปใบชั่งจะหายไป
- ผู้ใช้หลายคนจะไม่เห็นข้อมูลของกันและกัน
- **ควรกด "ดาวน์โหลดไฟล์สำรอง" ที่แท็บตั้งค่าเป็นประจำ** และเก็บไฟล์ `.json` ไว้

หากต้องใช้งานหลายเครื่องพร้อมกันหรือต้องการฐานข้อมูลกลาง จะต้องต่อยอดเป็นระบบที่มีเซิร์ฟเวอร์ฐานข้อมูล
ซึ่งอยู่นอกขอบเขตของเวอร์ชันนี้

## เมื่อไฟล์ Excel มีการแก้ไข

รัน **สองคำสั่งนี้ตามลำดับ** เพื่อสร้างฐานข้อมูลของเว็บใหม่
(ข้อมูลการรับซื้อใน localStorage ไม่ถูกลบ):

```bash
node eudr-web/tools/build-db.js
```

```bash
node eudr-web/tools/build-admin.js
```

```bash
node eudr-web/tools/build-protect.js
```

ต้องรันตามลำดับนี้เสมอ เพราะ `build-db.js` เขียน `data/db.js` ใหม่ทับ
ทำให้ฟิลด์ ตำบล/อำเภอ/พิกัดกลาง และผลตรวจเขตอนุรักษ์หายไป

ระบุพาธไฟล์ Excel เองได้:

```bash
node eudr-web/tools/build-db.js "C:\path\to\ไฟล์.xlsx"
```

ถ้าขอบเขตแปลงขยับออกนอกบริเวณเดิม ให้ดาวน์โหลดภาพดาวเทียมชุดใหม่ด้วย:

```bash
node eudr-web/tools/build-tiles.js
```

จากนั้นสร้างไฟล์เดียวจบสำหรับเผยแพร่เป็นลิงก์:

```bash
node eudr-web/tools/build-artifact.js
```

`build-artifact.js` จะเตือนถ้าไฟล์เกิน 16 MB ซึ่งเป็นเพดานของหน้าเว็บที่เผยแพร่ได้
ปัจจุบันอยู่ที่ 14.0 MB หากต้องการพื้นที่เพิ่ม ให้ลดระดับซูมสูงสุดของภาพดาวเทียมลง เช่น
`node eudr-web/tools/build-tiles.js 7 11`

สคริปต์จะพิมพ์ยอดสรุปแยกตามประเภทและเอกสารสิทธิ์ออกมา — **ควรเทียบกับชีต `พื้นที่ทั้งหมด(ไร่)`
ในไฟล์ Excel ทุกครั้ง** เพื่อยืนยันว่าการนำเข้าครบถ้วน

สคริปต์อ่าน `.xlsx` โดยตรงด้วย zlib ที่มากับ Node (ไม่ต้อง `npm install`) และรองรับชีตพ่อค้า
ที่มีขนาดราว 190 MB เมื่อคลายบีบอัดด้วยการอ่านแบบสตรีม

**ข้อควรระวังสองเรื่อง** ก่อนนำเว็บนี้ไปเผยแพร่ภายนอกองค์กรหรือใช้ประกอบเอกสารเชิงพาณิชย์

1. **ภาพดาวเทียมที่ฝังไว้ในไฟล์** เป็นการทำสำเนาภาพจาก Esri เก็บไว้ในเอกสารที่ส่งต่อได้
   ซึ่งต่างจากการเรียกดูผ่านบริการแผนที่ตามปกติ ถ้าจะแจกจ่ายออกนอกองค์กรควรตรวจสอบ
   เงื่อนไขของ Esri ก่อน หรือถอดชั้นภาพออกด้วยการลบ `data/tiles.js` แล้วสร้างไฟล์ใหม่
2. **ชั้นขอบเขตการปกครอง** มาจาก repo ที่ไม่ได้ระบุสัญญาอนุญาตไว้ หากต้องการความชัดเจน
   ทางกฎหมาย มีทางเลือกคือชุดข้อมูล COD-AB ของ UN OCHA (สัญญาอนุญาต CC BY-IGO) ที่
   [data.humdata.org/dataset/cod-ab-tha](https://data.humdata.org/dataset/cod-ab-tha)
   แต่ไฟล์มีขนาดใหญ่มาก (หลายร้อย MB) จึงต้องย่อขนาดก่อนใช้

ชั้นขอบเขตนี้ใช้ **เพื่อการอ้างอิงและช่วยระบุตำแหน่งเท่านั้น** ไม่ใช่ขอบเขตตามกฎหมาย
และถูกลดจำนวนจุดลง (ความคลาดเคลื่อนราว 25 เมตร) เพื่อให้ไฟล์เล็กพอสำหรับใช้งานบนเว็บ
